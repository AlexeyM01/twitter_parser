# NBA / Twitter → Telegram парсер

Автоматический бот, который каждые 10 минут проверяет новые твиты заданных
аккаунтов (NBA, ShamsCharania, TheDunkCentral) через Apify, скачивает их медиа
и публикует посты в Telegram-канал.

## Как работает программа

```
systemd-таймер (каждые 10 мин)
        │
        ▼
parser.py  ──►  Apify API  ──►  новые твиты за окно выборки
        │
        ├─► фильтр стоп-фраз (BLOCK_PHRASES) → пропуск ненужных твитов
        ├─► вырезание ссылок t.co из текста
        ├─► скачивание ВСЕХ медиа твита (до 10 — лимит альбома Telegram):
        │       1) прямые URL фото/видео из данных Apify (pbs/video.twimg.com)
        │       2) настоящие mp4 через резервный syndication API по tweet_id
        │       3) превью-картинка твита (отправляется как фото)
        ├─► отправка в Telegram:
        │       1 медиа  → sendPhoto/sendVideo с подписью
        │       2+ медиа → sendMediaGroup (альбом, подпись на первом файле;
        │                   при ошибке альбома — fallback на отправку по одному)
        │       0 медиа  → текстовый пост со ссылкой на оригинал
        └─► фиксация результата: sent_tweets.txt (ID отправленных) и
            parser_state.json (время последнего успешного запуска)
```

Ключевые свойства:

- **Окно выборки** считается от последнего успешного запуска с перекрытием 2 минуты
  — твиты, опубликованные на границе запусков, не теряются.
- **Защита от дублей**: ID сохраняется в `sent_tweets.txt` только после успешной
  отправки; при сбое сети/Telegram твит будет повторно отправлен при следующем запуске.
- **Догоняющее окно** после простоя ограничено 6 часами (`MAX_LOOKBACK_MIN`),
  чтобы не спамить старыми постами.
- **Один твит с ошибкой не останавливает** обработку остальных.
- Работает и с прокси (`PROXY_URL` в `.env`), и без него (на иностранном VPS
  прокси не нужен).

## Файлы проекта

### Рабочие (нужны везде)

| Файл | Описание |
|---|---|
| `parser.py` | Главный скрипт парсера. Вся логика: выборка твитов, фильтрация, медиа, отправка в Telegram. Константы не содержит — берёт их из `config.py` |
| `config.py` | **Вся конфигурация в одном месте**: секреты из `.env`, список аккаунтов мониторинга (`TWITTER_HANDLES`), стоп-фразы (`BLOCK_PHRASES`), параметры окна выборки и расписания, таймауты и лимиты. Менять настройки нужно только здесь |
| `requirements.txt` | Зависимости Python: `requests`, `apify-client`. Установка: `pip install -r requirements.txt` |
| `.gitignore` | Исключает из git секреты (`.env`), окружение (`venv/`), файлы состояния (`parser_state.json`, `sent_tweets.txt`) и кэш Python |

### Секреты (создаются вручную на сервере, в git не хранятся!)

| Файл | Описание |
|---|---|
| `.env` | Ключи доступа. Формат `KEY=VALUE`, права `chmod 600`: `APIFY_TOKEN` — токен Apify; `ACTOR_ID` — ID скрапера (вид `ник~название`); `TG_BOT_TOKEN` — токен бота из @BotFather; `TG_CHAT_ID` — ID канала (`-100…`); `PROXY_URL` — опционально |

### Файлы состояния (создаются скриптом на сервере автоматически)

| Файл | Описание |
|---|---|
| `sent_tweets.txt` | ID уже отправленных твитов — защита от дублей. Автоматически обрезается до последних 20 000 записей |
| `parser_state.json` | Время последнего успешного запуска — от него считается окно выборки. Можно удалить для «чистого» теста (окно станет 15 минут) |

### Systemd-юниты (устанавливаются в `/etc/systemd/system/`)

| Файл | Описание |
|---|---|
| `twitter-parser.service` | **Актуальный юнит**. Описание разовой задачи для systemd: рабочая папка, путь к скрипту, файл секретов, лимит времени 10 минут |
| `twitter-parser.timer` | **Актуальный таймер**: запуск сервиса каждые 10 минут, первый прогон через 2 минуты после загрузки сервера, `Persistent=true` догоняет пропущенные запуски |
| `nba-parser.service` | Старая версия юнита (пути `/opt/nba-parser`, файл `/etc/nba-parser.env`). Оставлена для справки; при установке не используется |
| `nba-parser.timer` | Старая версия таймера. Не используется вместе с `twitter-parser.*` — двойной запуск даст дубли |

### Утилиты

| Файл | Описание |
|---|---|
| `deploy.sh` | Автоустановка «с нуля» на Ubuntu/Debian: проверяет `.env`, создаёт venv, ставит зависимости и копирует юниты systemd. Ожидает рядом `.env`, `parser.py` и `config.py`. Запуск: `sudo bash deploy.sh`. Используйте только при новой установке; для обновления кода достаточно `git pull` |

## Управление на сервере

```bash
# Расписание / статус
systemctl list-timers | grep twitter

# Разовый запуск и логи
systemctl start twitter-parser.service
journalctl -u twitter-parser.service -f        # живой лог
journalctl -u twitter-parser.service --since today   # лог за день

# Итоги всех запусков за день (счётчики: дубли, отфильтровано, отправлено, ошибки)
journalctl -u twitter-parser.service --since today | grep "Итог запуска"

# Включить / выключить автозапуск
systemctl enable --now twitter-parser.timer
systemctl disable --now twitter-parser.timer

# Обновить код с GitHub (перезапуск не нужен — новый код подхватится сам)
cd /root/twitter_parser && git pull
```

## Настройка

- **Аккаунты для мониторинга**: список `TWITTER_HANDLES` в `config.py`.
- **Стоп-фразы** (твит не публикуется): список `BLOCK_PHRASES` в `config.py`.
- **Интервал запуска**: `RUN_INTERVAL_MIN` / `OVERLAP_MIN` в `config.py` (значение `RUN_INTERVAL_MIN` должно совпадать с `OnUnitActiveSec` в `twitter-parser.timer`).
- **Таймауты и лимиты**: `SYNDICATION_TIMEOUT`, `DOWNLOAD_TIMEOUT`, `TG_*_TIMEOUT`, `MAX_ITEMS` и др. — в `config.py`.
