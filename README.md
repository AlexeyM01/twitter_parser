# Shams Charania (X) → Telegram-канал

Парсер берёт новые посты [x.com/ShamsCharania](https://x.com/ShamsCharania) (Шэмс Чарания, ESPN — главный NBA-инсайдер) и публикует их в ваш Telegram-канал: перевод на русский, картинки из твита, ссылка на оригинал. Запуск — бесплатно на GitHub Actions по расписанию.

**my.telegram.org не нужен**: публикация идёт от имени бота, токен выдаёт @BotFather прямо в Telegram (работает в России без VPN). Старый режим через личный аккаунт (Telethon) тоже сохранён — он включается автоматически, если задать `TELEGRAM_SESSION`.

## Как устроено

```
RSSHub (RSS-лента профиля) → parser.py → перевод → Bot API → ваш канал
                                  ↓
                             state.json (какие твиты уже опубликованы,
                             коммитится обратно в репозиторий)
```

| Файл | Назначение |
| --- | --- |
| `parser.py` | Основной скрипт: RSS → новые посты → перевод → медиа → Telegram |
| `.github/workflows/shams.yml` | Запуск каждые 20 минут на GitHub Actions |
| `state.json` | Состояние (создаётся автоматически при первом запуске) |
| `sample_feed.xml` | Тестовая лента для проверки форматирования без сети |
| `.env.example` | Шаблон настроек для локального запуска |
| `generate_session.py` | Только для опционального режима «личный аккаунт» |

## Настройка за 5 шагов (без my.telegram.org)

### Шаг 1. Создайте бота — 1 минута

1. В Telegram откройте [@BotFather](https://t.me/BotFather) (официальный бот, доступен в РФ).
2. Команда `/newbot` → придумайте имя (например, `Shams NBA`) и username (например, `my_shams_news_bot`).
3. BotFather пришлёт **токен** вида `7123456789:AAE8k...` — это `TELEGRAM_BOT_TOKEN`.

Бот будет автором постов в канале. Внешне это неотличимо от обычного канала: боту можно поставить имя, аватарку и описание (команда `/setuserpic`).

### Шаг 2. Добавьте бота в канал

1. Откройте ваш канал → Управление каналом → Администраторы → **Добавить администратора**.
2. Найдите вашего бота по username.
3. Дайте право **«Публикация сообщений»** (остальные права не нужны).

`TELEGRAM_CHANNEL` — это `@имя_канала` (публичный) или числовой id (приватный; узнать: добавьте в канал любого бота типа @getidsbot, либо возьмите `-100...` из адреса веб-версии).

### Шаг 3. Репозиторий и секреты

1. Создайте репозиторий на GitHub (публичный или приватный) и загрузите туда все файлы этой папки — структура как здесь, воркфлоу обязательно в `.github/workflows/`.
2. GitHub → Settings → **Secrets and variables → Actions** → вкладка Secrets:

| Секрет | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен из шага 1 |
| `TELEGRAM_CHANNEL` | `@имя_канала` из шага 2 |

3. Там же во вкладке **Variables** можно (необязательно) переопределить: `TRANSLATOR` (`google_free` / `deepl` / `off`), `RSSHUB_INSTANCES`, `CUSTOM_RSS_URL`, `MAX_POSTS_PER_RUN`.

### Шаг 4. Первый запуск

GitHub → вкладка **Actions** → workflow «Shams → Telegram» → **Run workflow**.

Первый запуск работает в «тихом» режиме: скрипт запоминает текущие твиты в `state.json`, но **ничего не публикует** — чтобы канал не завалили старые новости. Все последующие твиты Шэмса будут приходить в канал автоматически каждые 20 минут.

### Шаг 5. RSS-источник — самое важное

Скрипт по очереди пробует источники из `RSSHUB_INSTANCES` и `CUSTOM_RSS_URL` (роут RSSHub: `/twitter/user/ShamsCharania`).

⚠️ **У большинства публичных RSSHub-инстансов Twitter-роут отключён** (ошибка «Twitter API is not configured»), а бесплатные зеркала X закрываются. Поэтому надёжный вариант — **свой RSSHub**. Это 10 минут и бесплатно:

1. Возьмите любую дешёвую VPS (или домашний сервер, который всегда включён).
2. Выполните:

```bash
mkdir rsshub && cd rsshub && cat > docker-compose.yml <<'EOF'
services:
  rsshub:
    image: diygod/rsshub:latest
    restart: always
    ports:
      - "1200:1200"
    environment:
      NODE_ENV: production
      CACHE_EXPIRE: 600
      # Ниже — auth_token из cookie вашего залогиненного x.com
      # (DevTools -> Application -> Cookies -> https://x.com -> auth_token).
      # Актуальные переменные роута Twitter: docs.rsshub.app -> Configure -> Twitter.
      TWITTER_AUTH_TOKEN: "ВСТАВЬТЕ_ЗНАЧЕНИЕ"
EOF
docker compose up -d
```

3. Проверьте: `http://ВАШ_IP:1200/twitter/user/ShamsCharania` должен отдавать XML.
4. В Secrets/Variables репозитория добавьте Variable:
   `CUSTOM_RSS_URL` = `http://ВАШ_IP:1200/twitter/user/ShamsCharania`.

Частный случай — если у вас уже есть рабочий инстанс RSSHub, просто укажите его в `RSSHUB_INSTANCES`.

## Перевод на русский

| Режим | Как включить | Комментарий |
| --- | --- | --- |
| Google (бесплатно) | `TRANSLATOR=google_free` (по умолчанию) | Без ключей. Иногда упирается в лимиты — тогда пост выйдет на английском, ничего не сломается |
| DeepL | `TRANSLATOR=deepl` + секрет `DEEPL_API_KEY` | Стабильнее. Free-ключ: https://www.deepl.com/pro-api (500 000 знаков/мес бесплатно, для Шэмса хватает с запасом) |
| Без перевода | `TRANSLATOR=off` | Публикуется оригинальный текст |

Перевод идёт через `deep-translator` (Google) или DeepL API; ссылки внутри твита защищены от порчи переводчиком.

## Опционально: публикация от имени личного аккаунта

Если хотите, чтобы посты выходили «от вашего имени» (а не от бота), используется режим Telethon. Для него нужны api_id/api_hash с https://my.telegram.org — **если сайт не открывается, включите VPN только на время одного визита**: данные получаете один раз, дальше сайт не нужен. Затем:

```bash
pip install telethon
python generate_session.py   # напечатает TELEGRAM_SESSION
```

И добавьте секреты `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION`. Ваш аккаунт должен быть админом канала. Если `TELEGRAM_SESSION` задан, он имеет приоритет… точнее наоборот: **при заданном `TELEGRAM_BOT_TOKEN` парсер использует бота**, сессия включается только когда токена нет.

## Локальный запуск (без GitHub Actions)

```bash
pip install -r requirements.txt
cp .env.example .env        # заполните переменные

# тест без Telegram: показать, что было бы отправлено (state не меняется)
TEST_FEED=sample_feed.xml TRANSLATOR=off python parser.py --dry-run

# рабочий режим
python parser.py
```

Для «всегда включённого» локального запуска удобно держать цикл:

```bash
while true; do python parser.py; sleep 1200; done
```

## Частые вопросы

**Посты идут от имени бота — можно ли от канала?** Да, это и есть «от канала»: в Telegram посты канала показываются от имени канала, подпись автора (бота) видна только при желании. Визуально лента выглядит штатной.

**Бот пишет «Unauthorized» / «bot is not a member»?** Проверьте токен и что бот добавлен **администратором** именно этого канала (шаг 2).

**Пост выйдет дважды?** Нет: id твитов сохраняются в `state.json` (до 500 последних), повторная публикация исключена даже после перезапуска.

**Шэмс выпустил сразу 10 твитов?** За один запуск уйдёт не больше `MAX_POSTS_PER_RUN` (по умолчанию 5) самых свежих, остальное — на следующих запусках. Посты старше `MAX_AGE_HOURS` часов пропускаются.

**Ретвиты?** По умолчанию не публикуются (`SKIP_RETWEETS=true`).

**Сколько стоит GitHub Actions?** Публичный репозиторий — бесплатно без лимитов. Приватный — ~1500 мин/мес при кроне `*/20` (лимит 2000); поставьте `*/30` в `.github/workflows/shams.yml`, чтобы снизить расход.

**Сообщения с длинным текстом и картинками?** Подпись альбома ограничена 1024 знаками: если текст длиннее, скрипт отправит альбом, а текст — отдельным сообщением-ответом на него.

**Насколько это законно/надёжно?** RSSHub использует неофициальный доступ к X: токен может перестать работать, а доступ к X через неофициальные средства формально нарушает ToS X. Для персонального канала это обычная практика, но стопроцентной надёжности у бесплатного способа быть не может.
